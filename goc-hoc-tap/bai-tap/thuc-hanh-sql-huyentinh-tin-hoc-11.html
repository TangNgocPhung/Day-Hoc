Thực hành truy vấn SQL trên CSDL MyList (huyện – tỉnh)

Khai thác CSDL gồm danh sách các huyện, tỉnh và bảng liên kết giữa chúng: nối 3 bảng, lọc theo điều kiện và tìm kiếm theo mẫu bằng LIKE.

1 Mục tiêu và chuẩn bị

Sau bài thực hành, em có thể:

  • Nhận biết bảng trung gian (danhsach) biểu diễn quan hệ nhiều – nhiều giữa huyện và tỉnh.
  • Nối 3 bảng bằng JOIN … ON … để thay các mã số bằng tên huyện, tên tỉnh.
  • Dùng WHERE với phép so sánh = và toán tử LIKE.
  • Hiểu ảnh hưởng của bảng mã đối chiếu _ci đến kết quả so sánh chuỗi tiếng Việt.

Cách làm:

  1. Mở HeidiSQL, kết nối máy chủ MySQL/MariaDB (như Bài 17–20), chọn CSDL mylist ở khung bên trái.
  2. Mở thẻ Query (hoặc nhấn Ctrl+T để mở thẻ truy vấn mới), gõ câu lệnh SQL rồi bấm nút ▶ hoặc nhấn F9 để chạy.
  3. Kết quả hiện ở khung bên dưới. Em so sánh với bảng Kết quả mong đợi trong phần hướng dẫn giải.
💡

Hãy tự làm trước, xem lời giải sau. Mỗi câu có ô để em viết nháp câu lệnh. Chỉ mở phần Xem hướng dẫn giải khi đã thử ít nhất một lần.

2 Cơ sở dữ liệu MYLIST

CSDL MyList lưu tên các huyện, tên các tỉnh và danh sách cho biết huyện nào có ở tỉnh nào. Nhiều huyện trùng tên ở các tỉnh khác nhau (ví dụ Châu Thành, An Lão), nên không thể ghi thẳng “tỉnh” vào bảng huyện mà cần bảng trung gian danhsach.

2.1. Lược đồ quan hệ

Gạch chân là khoá chính, in nghiêng là khoá ngoài.

huyen (idHuyen, tenHuyen)
tinh (idTinh, tenTinh)
danhsach (idDS, idHuyen, idTinh)

3 Tạo CSDL và nhập dữ liệu mẫu

Em chưa có CSDL này? Hãy tạo CSDL mylist bằng script dưới đây (chạy trong thẻ Query của HeidiSQL). Script tạo 3 bảng có khoá chính, khoá ngoài và nhập sẵn dữ liệu mẫu.

Xem script tạo bảng và nhập dữ liệu (bấm để mở)
SQL · mylist.sql
-- Tạo CSDL mylist và nhập dữ liệu mẫu (chạy trong thẻ Query của HeidiSQL)
CREATE DATABASE IF NOT EXISTS mylist CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
USE mylist;

DROP TABLE IF EXISTS danhsach;
DROP TABLE IF EXISTS tinh;
DROP TABLE IF EXISTS huyen;

CREATE TABLE huyen (
  idHuyen INT NOT NULL AUTO_INCREMENT,
  tenHuyen VARCHAR(255) NOT NULL DEFAULT '',
  PRIMARY KEY (idHuyen)
) ENGINE=InnoDB;

CREATE TABLE tinh (
  idTinh INT NOT NULL AUTO_INCREMENT,
  tenTinh VARCHAR(255) NOT NULL DEFAULT '',
  PRIMARY KEY (idTinh)
) ENGINE=InnoDB;

CREATE TABLE danhsach (
  idDS INT NOT NULL AUTO_INCREMENT,
  idHuyen INT NOT NULL,
  idTinh INT NOT NULL,
  PRIMARY KEY (idDS),
  UNIQUE KEY uq_danhsach (idHuyen, idTinh),
  CONSTRAINT FK_danhsach_huyen FOREIGN KEY (idHuyen) REFERENCES huyen (idHuyen),
  CONSTRAINT FK_danhsach_tinh FOREIGN KEY (idTinh) REFERENCES tinh (idTinh)
) ENGINE=InnoDB;

4 Bài tập truy vấn dữ liệu

Em hãy viết các truy vấn sau. Viết các câu lệnh trong HeidiSQL, so sánh kết quả với đáp án.

0 / 4 câu
Câu 1Nối 3 bảng

Truy xuất dữ liệu mã danh sách, tên huyện, tên tỉnh.

Bảng liên quan: danhsach, huyen, tinh

Xem hướng dẫn giải câu 1

Phân tích

  1. Ba cột đến từ ba bảng: idDS (danhsach), tenHuyen (huyen), tenTinh (tinh).
  2. danhsach chứa hai khoá ngoài idHuyen, idTinh → là bảng trung gian, dùng làm điểm xuất phát.
  3. Nối ds.idHuyen = h.idHuyen và ds.idTinh = t.idTinh. Không lọc nên lấy đủ 10 dòng.

Câu lệnh SQL

SQL
SELECT ds.idDS, h.tenHuyen, t.tenTinh
FROM danhsach ds
JOIN huyen h ON ds.idHuyen = h.idHuyen
JOIN tinh  t ON ds.idTinh  = t.idTinh;

Câu 2Nối 3 bảng · lọc

Hãy cho biết tỉnh Bến Tre có những huyện nào.

Bảng liên quan: danhsach, huyen, tinh

Xem hướng dẫn giải câu 2

Phân tích

  1. Cần hiển thị tenHuyen; điều kiện theo tenTinh → dùng lại cấu trúc nối 3 bảng của câu 1.
  2. Thêm WHERE t.tenTinh = 'Bến Tre' và chỉ chọn cột h.tenHuyen.

Câu lệnh SQL

SQL
SELECT h.tenHuyen
FROM danhsach ds
JOIN huyen h ON ds.idHuyen = h.idHuyen
JOIN tinh  t ON ds.idTinh  = t.idTinh
WHERE t.tenTinh = 'Bến Tre';

Câu 4LIKE · 1 bảng

Tìm những tỉnh (idTinh, tenTinh) có từ “Hà”.

Bảng liên quan: tinh

Xem hướng dẫn giải câu 4

Phân tích

  1. Chỉ cần bảng tinh, lấy idTinh, tenTinh.
  2. “Có từ Hà” → từ này có thể ở đầu, giữa hoặc cuối tên → mẫu '%Hà%' (dấu % ở cả hai đầu).
  3. Chạy thử và quan sát kết quả cẩn thận — nó có thể không như em nghĩ!

Câu lệnh SQL

SQL
SELECT idTinh, tenTinh
FROM tinh
WHERE tenTinh LIKE '%Hà%';
⚠️

Vì sao có cả “Đồng Tháp” và “Hải Phòng”?

CSDL ở Bài 19 dùng bảng mã đối chiếu utf8mb4_general_ci. Hậu tố _ci (case-insensitive) khiến MySQL/MariaDB coi chữ hoa và chữ thường là như nhau, đồng thời bỏ qua dấu khi so sánh: à, á, ả, ã, ạ đều được xem như “a”. Vì vậy “Hà” ≡ “Ha” ≡ “Há” ≡ “Hả” và mẫu '%Hà%' khớp với “Đồng Tháp”, “Hà Nội”, “Hải Phòng”.

Muốn chỉ lấy đúng “Hà Nội”?

Ép so sánh theo từng byte (phân biệt dấu và chữ hoa/thường) bằng từ khoá BINARY:

SQL
SELECT idTinh, tenTinh
FROM tinh
WHERE tenTinh LIKE BINARY '%Hà%';

Kết quả (1 dòng)

idTinhtenTinh
5Hà Nội

Hoặc nếu hiểu “từ Hà” là đứng đầu tên thì viết LIKE BINARY 'Hà%' — kết quả vẫn là “Hà Nội”.

Kết quả khi chạy trong HeidiSQL với CSDL mặc định (3 dòng)

idTinhtenTinh
4Đồng Tháp
5Hà Nội
6Hải Phòng
💡

Cách nào đúng? Cả hai đều đúng với cách hiểu khác nhau về đề bài. Nếu đề muốn tìm gần đúng, không cần nhớ dấu (như ô tìm kiếm thông thường) thì kết quả 3 dòng là hợp lí; nếu cần khớp chính xác từ “Hà” thì dùng BINARY. Hãy chạy cả hai và giải thích sự khác nhau.

5 Tổng kết

Bảng trung gianQuan hệ nhiều – nhiều giữa hai bảng được biểu diễn bằng một bảng thứ ba chứa hai khoá ngoài.
Nối theo khoáTừ bảng trung gian, nối lần lượt với từng bảng gốc: ds.idHuyen = h.idHuyen, ds.idTinh = t.idTinh.
Lọc theo tênĐiều kiện WHERE viết trên cột tên (tenTinh, tenHuyen) sau khi đã nối.
Cẩn thận với LIKEVới bảng mã _ci, so sánh không phân biệt hoa/thường và không phân biệt dấu. Dùng LIKE BINARY khi cần khớp chính xác.
